# INF-9 — Автоматическое ревью выключено, и об этом ничего не говорит

- **Эпик:** E0 — Scaffolding & инфраструктура
- **Статус:** done
- **Зависимости:** INF-4, INF-7
- **Критический путь:** нет

## Описание

Воркфлоу `Claude code review` в состоянии `disabled_manually`:

```
$ gh workflow list --all
Claude code review   disabled_manually   305563943
Quality gate         active              305563942
```

Последний его прогон — 29 октября 18:33 UTC на ветке RUN-4. Все 14 PR, открытых
после этого (#29 → #42), автоматического ревью не получили, и ни один из них этого
не показал: выключенный воркфлоу не даёт ни красного чека, ни предупреждения — он
просто отсутствует в списке проверок.

## Контекст

До выключения он падал на каждом PR. Причина видна в логе прогона `40931976946`:

```
"anthropic_api_key": "",
"claude_code_oauth_token": "",
##[error]Action failed with error: Environment variable validation failed:
```

Секретов в репозитории нет ни одного (`gh secret list` пуст), поэтому action падал
на валидации окружения.

**Почему не помогла защита из [INF-7](INF-7.md).** Не «не помогла» — её ни разу не
проверяли. [INF-7](INF-7.md) добавил ровно то, что нужно для этого случая:
`HAS_API_KEY: ${{ secrets.ANTHROPIC_API_KEY != '' }}` в job-level `env`, шаги ревью
под условием и шаг с `::warning::`, когда секрета нет. Имя переменной совпадает с
тем, чего не хватало: воркфлоу с самого начала ([INF-4](INF-4.md), коммит `8b9b7e1`)
передавал в action `anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}`, а
`claude_code_oauth_token` в логе пуст просто потому, что action печатает все свои
входы.

Дело в хронологии. Последний прогон ревью — 2026-10-29 18:33 UTC, мерж INF-7 (#31) —
2026-10-29 20:11 UTC. То есть воркфлоу выключили **до** того, как починка попала в
`main`, и с тех пор он не запускался ни разу — даже на PR самого INF-7. Всего 29
прогонов за всю историю воркфлоу, последний из них и есть тот, что в логе выше.
INF-7 починил проверку вслепую, и подтвердить это было нечем.

Первая версия этого тикета объясняла молчание иначе: мол, защита привязана к
`ANTHROPIC_API_KEY`, а action аутентифицируется через `CLAUDE_CODE_OAUTH_TOKEN`,
поэтому джоба «снова стала падать и её отключили руками». Это неверно в обе
стороны — имена совпадают, и после INF-7 падений не было, потому что не было
прогонов. Настоящая причина проще и хуже: тумблер выключили и забыли, а выключенный
воркфлоу об этом не сообщает. Цена ошибки — 14 PR без ревью, включая тот, которым
эту самую проверку починили.

**Почему это та же ошибка, что INF-7 называл главной.** Вывод INF-7 был: пропускать
ревью молча нельзя, потому что зелёный чек читается как «ревью прошло». Выключенный
воркфлоу хуже: он не даёт даже зелёного чека — он не даёт ничего, и отсутствие
проверки выглядит как норма.

## Решение

Выбрано: **удалить воркфлоу**. Отсутствие автоматического ревью становится
записанным решением, а не забытым тумблером.

Альтернатива — задать секрет и включить — отклонена владельцем репозитория. Третий
вариант, «включить без секрета», отклонён сразу: воркфлоу отдавал бы зелёный чек с
предупреждением внутри прогона, то есть ровно ту картину «проверка прошла», против
которой писался INF-7.

- Удалить `.github/workflows/claude-review.yml`.
- В README сказать, что AI-ревью нет и почему, и что обязательных проверок на PR
  осталось ровно одна — Quality gate.
- Убрать упоминание ревью из PR template, сохранив требование указывать тикет: по
  нему сверяется DoD, теперь человеком.

## Критерии приёмки (DoD)

- [x] Воркфлоу либо работает, либо удалён из репозитория. Состояния «лежит
      выключенным» не остаётся.
- [x] В README сказано, какие проверки обязательны на PR и какие из них требуют
      секретов, чтобы «проверки не было» нельзя было спутать с «проверка прошла».
- [x] Упоминания удалённого воркфлоу не осталось в действующих документах.

## Как сделано

### Объём

Удалён `.github/workflows/claude-review.yml` (85 строк). Правки в
[README.md](../README.md) (раздел «CI и код-ревью») и
[PR template](../.github/pull_request_template.md). Кода и тестов правка не
касается.

### Что теперь сказано в README

Раздел «CI и код-ревью» переписан: один обязательный пайплайн вместо двух, и прямо
сказано, что AI-ревью нет и почему — воркфлоу лежал выключенным, не давал ни чека,
ни предупреждения, и 14 PR подряд прошли без ревью так, что заметить это можно было
только через `gh workflow list`.

Требование указывать тикет в теле PR сохранено, но с честной причиной: раньше по ID
тикета воркфлоу находил DoD для сверки, теперь по нему сверяется DoD человеком.

### Заодно: branch protection не настроена

Проверка `gh api repos/flank911/researcher/branches/main/protection` отвечает
`Branch not protected`, тогда как README утверждал: «запрещён прямой push в `main` —
только через PR» и «падение любого шага блокирует merge». Это не теория: именно
поэтому красный после [RUN-8](RUN-8.md) py3.11 спокойно прожил три мержа (#39 → #41)
и был найден только в [INF-8](INF-8.md).

Правка README этот абзац задевала напрямую — оставить в нём заведомо ложное
утверждение было нельзя, поэтому раздел переписан на то, что есть, с подразделом
«Чего в репозитории не настроено» и инструкцией. Само включение ruleset — действие
владельца репозитория и отдельный тикет; здесь только исправлена документация.

### Что не тронуто

[INF-4](INF-4.md) и [INF-7](INF-7.md) оставлены как есть. Они верно описывают, что
было сделано тогда; переписывать закрытые тикеты под сегодняшнее решение значило бы
стирать историю. INF-4 построил два пайплайна, INF-9 оставил один — это видно по
реестру, а не по правкам в закрытых тикетах.

История прогонов удалённого воркфлоу остаётся в Actions: удаление файла убирает
воркфлоу из репозитория, но не стирает 29 прошлых прогонов.
