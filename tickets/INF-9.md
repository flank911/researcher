# INF-9 — Автоматическое ревью выключено, и об этом ничего не говорит

- **Эпик:** E0 — Scaffolding & инфраструктура
- **Статус:** todo
- **Зависимости:** INF-4, INF-7
- **Критический путь:** нет

## Описание

Воркфлоу `Claude code review` в состоянии `disabled_manually`:

```
$ gh workflow list --all
Claude code review   disabled_manually   305563943
Quality gate         active              305563942
```

Последний его прогон — 29 октября на ветке RUN-4. PR #35–#40 автоматического ревью
не получили, и ни один из них этого не показал: выключенный воркфлоу не даёт ни
красного чека, ни предупреждения — он просто отсутствует в списке проверок.

## Контекст

До выключения он падал на каждом PR. Причина видна в логе прогона
`40931976946`:

```
"claude_code_oauth_token": "",
CLAUDE_CODE_OAUTH_TOKEN:
ANTHROPIC_OIDC_AUDIENCE:
```

Секрет не задан, action падает на валидации окружения.

**Почему не помогла защита из [INF-7](INF-7.md).** Там ровно этот случай уже
разбирался и был закрыт: добавлены `HAS_API_KEY` в job-level `env`, шаги ревью под
условием и шаг с `::warning::` и инструкцией, когда секрета нет. Но проверялась
переменная `ANTHROPIC_API_KEY`, а action аутентифицируется через
`CLAUDE_CODE_OAUTH_TOKEN` (или OIDC). Новое имя под условие не попало, поэтому
механизм «пропустить с предупреждением» на него не распространился, джоба снова
стала падать — и её отключили руками.

То есть INF-7 исправил случай, а не класс: защита была привязана к имени секрета, а
не к факту «учётных данных нет».

**Почему это та же ошибка, что INF-7 называл главной.** Вывод INF-7 был:
пропускать ревью молча нельзя, потому что зелёный чек читается как «ревью прошло».
Выключенный воркфлоу хуже: он не даёт даже зелёного чека — он не даёт ничего, и
отсутствие проверки выглядит как её отсутствие в списке, то есть как норма. Шесть
PR подряд прошли без ревью, и заметить это можно было только через `gh workflow
list`.

## Решение

Выбрать одно из двух и не оставлять третьего:

1. **Задать секрет** `CLAUDE_CODE_OAUTH_TOKEN` в настройках репозитория и включить
   воркфлоу (`gh workflow enable`). Это действие владельца репозитория.
2. **Удалить воркфлоу** из репозитория, если автоматическое ревью не нужно. Тогда
   отсутствие ревью — записанное решение, а не забытый тумблер.

Если выбран первый путь, заодно починить обобщение, на котором INF-7 остановился:
условие пропуска должно срабатывать по **любому** отсутствующему способу
аутентификации, а не по конкретному имени переменной, и печатать `::warning::` с
тем, чего не хватает.

## Критерии приёмки (DoD)

- [ ] Воркфлоу либо работает (секрет задан, прогон зелёный на живом PR), либо
      удалён из репозитория. Состояния «лежит выключенным» не остаётся.
- [ ] Если оставлен: отсутствие учётных данных даёт видимое предупреждение, а не
      падение и не тишину — проверено прогоном без секрета.
- [ ] В README сказано, какие проверки обязательны на PR и какие из них требуют
      секретов, чтобы «проверки не было» нельзя было спутать с «проверка прошла».
