# EXP-5 — Параллельное исполнение

- **Эпик:** E3 — Experiment Engine
- **Статус:** done
- **Зависимости:** EXP-4

## Описание

Параллельный запуск прогонов.

- Process pool воркеров; каждый воркер пишет свой Parquet-партишн результатов.
- Агрегатор сводит `run_metrics` в каталог.
- Совместимость с dedupe/resume (EXP-3).

## Критерии приёмки (DoD)

- [x] Ускорение близко к числу доступных ядер.
- [x] Отсутствие гонок при записи (повтор теста EXP-4 под нагрузкой).
- [x] Падение одного воркера не рушит весь эксперимент; resume доделывает.

## Примечание

- `experiments/parallel.py` (`execute_runs_parallel`): `ProcessPoolExecutor`
  распределяет `compute(spec)`; сохраняет семантику EXP-3 — dedupe (готовые раны
  не отправляются) и resume (маркер `RunLedger` пишется в главном процессе только
  после успеха воркера). Исключение одного рана фиксируется в `failed_hashes`,
  остальные доводятся до конца; при рестарте упавшие доделываются.
- `compute` должен быть picklable (функция уровня модуля / `functools.partial`) —
  уходит в дочерний процесс; агрегатором метрик служит сам `ResultsStore` (EXP-4).
- Укреплён `ResultsStore` для многопроцессной записи: окно первичного создания БД
  (до установления WAL) `busy_timeout` не покрывает — добавлен retry-on-locked
  вокруг операций записи (иначе ~единицы процентов ранов падали с «database is
  locked»).
