# ADM-3 — Веб-админка: каркас только для чтения и страница данных

- **Эпик:** E10 — Админка
- **Статус:** done
- **Зависимости:** ADM-1, ADM-2
- **Критический путь:** да (каркас для ADM-4…ADM-7)

## Описание

Локальный веб-интерфейс к состоянию платформы: страница «Данные» (покрытие,
свежесть, retention, дефекты) и каркас, на который встают остальные страницы
эпика. На этом шаге приложение **не умеет ничего менять**.

## Контекст: почему веб, а не терминал и не ноутбук

Варианты рассматривались в таком порядке.

| Вариант | Почему не он |
|---|---|
| Только `status` в терминале ([ADM-2](ADM-2.md)) | Отвечает «всё ли живо», но не даёт углубиться: 684 прогона, 19 слайсов и 6 пар в строках терминала не разглядеть, heatmap не нарисовать |
| Ноутбук (как `004_first_research.ipynb`) | Уже есть и уже недостаточен: требует venv, ядра и исполнения сверху вниз; это отчёт о прогоне, а не наблюдение за платформой |
| TUI (Textual) | Ближе всего к стеку, но графики в терминале — компромисс, а именно карты параметров и equity нужны глазами |
| Streamlit | Быстрее всего до первой картинки, но вся логика живёт в скрипте, который перезапускается на каждый клик: `mypy strict` и 591 тест такой код не удержат, а проект держится именно на этом |
| FastAPI + серверный HTML | Выбран |

Серверный HTML (Jinja) без фронтенд-фреймворка: страницы отдаются готовыми,
обновление блока статуса — опрос через HTMX. Графики — существующий matplotlib
(`analytics/plots.py`, `heatmap_to_png` уже отдаёт PNG в память) и inline SVG для
простых линий. Тестируется `TestClient`'ом как обычные функции.

Зависимости (`fastapi`, `uvicorn`, `jinja2`) идут **отдельной экстрой** `admin`
— тем же приёмом, которым вынесен `backtesting` для golden-теста
([BT-8](BT-8.md)): базовая установка платформы не должна тянуть веб-сервер.

## Решение

- `trading-research admin [--port 8787] [--config <path>]`; слушает только
  `127.0.0.1`, без аутентификации — потому что снаружи не доступен.
- Страницы этого тикета: «Обзор» (те же четыре блока, что `status`) и «Данные»
  (таблица пара × ряд: покрытие, последняя точка, отставание, запас retention,
  вердикт валидации с его датой, список пропусков из отчёта).
- Ни одного `POST`: контроль — [ADM-6](ADM-6.md). До него админка физически не
  может ничего запустить и ничего испортить.
- Данные берутся только из read-model [ADM-1](ADM-1.md); приложение не знает ни
  про parquet, ни про sqlite.

## Критерии приёмки (DoD)

- [x] Тесты через `TestClient` на двух состояниях: пустой store и наполненный;
      страница пустого store не падает, а объясняет, что данных нет.
- [x] Числа на странице «Обзор» совпадают с выводом `status --json` — тест на
      согласованность: одна правда, два вида.
- [x] `mypy strict` и `ruff` зелёные на новом пакете; веб-зависимости только в
      экстре `admin`, базовая установка их не требует (проверено импорт-тестом).
- [x] В приложении нет ни одного обработчика, меняющего состояние — проверяется
      тестом по таблице маршрутов (все методы `GET`).
- [x] Занятый порт даёт понятное сообщение и код возврата, а не трейс.
- [x] Время ответа страницы «Данные» на сегодняшнем store замерено и записано.

## Как сделано

### Что получилось

```
$ trading-research admin
админка (только чтение) -> http://127.0.0.1:8787
```

Две страницы. «Обзор» — те же блоки, что печатает `status`, плюс таблица рядов и
walk-forward. «Данные» — таблица пара × ряд: покрытие, строк, отставание, запас
retention, когда проверяли и вердикт. `/api/status` отдаёт тот же payload, что
`status --json`.

### Три решения

**Одна правда на две поверхности.** Страницы не считают ничего своего: строки
блоков «Расписание», «Валидация» и «Эксперименты» — это буквально результат
`describe_schedule`/`describe_validation`/`describe_results` из
[ADM-2](ADM-2.md), а `/api/status` — результат `status_payload`. Тест сравнивает
их с выводом CLI на одном и том же store. Причина строгая: расхождение числа в
терминале и на странице хуже отсутствия страницы — после него нельзя верить ни
одному из двух.

**Состояние читается на каждый запрос, кэша нет.** Сборка состояния на
сегодняшнем store — 0,20 с (измерено ниже), а страница, показывающая вчерашнюю
свежесть данных, отвечает не на тот вопрос, ради которого открыта.

**Ни одного внешнего адреса.** Ни CDN, ни шрифтов, ни иконок: CSS вшит в
`base.html`, тёмная тема — через `prefers-color-scheme`. Админка должна
открываться на машине без интернета, и то же свойство потребуется снимку отчёта
([ADM-7](ADM-7.md)). Поэтому HTMX, названный в плане тикета, **не взят**: он
либо внешний адрес, либо вендоренный файл, а обновление страницы — это F5.
Графики (`heatmap_to_png`) тоже остались за рамками: им нужна страница прогонов,
то есть [ADM-4](ADM-4.md).

### Отступления от плана тикета

| План | Сделано | Почему |
|---|---|---|
| Обновление блока статуса через HTMX | Перезагрузка страницы | HTMX — внешний адрес либо вендоринг; выигрыш не стоит ни того, ни другого |
| Графики matplotlib на этих страницах | Перенесены в ADM-4 | Карты параметров и equity принадлежат странице прогонов, а не странице данных |
| Флаг `--config` в описании решения | Есть, плюс `--data-root`/`--results-root`/`--reports-root`/`--log` | Те же флаги, что у `status`: админка открывается на той же конфигурации, что проверяется в терминале |

Флага `--host` **нет намеренно**: аутентификации у админки нет, и одна опция не
должна открывать снаружи интерфейс, где видно всё состояние исследования. Нужен
доступ с другой машины — SSH-туннель, то есть осознанное решение. Проверено на живом
сервере: `POST /` отвечает `405`, а запрос на `http://192.168.0.60:8791/` (адрес
машины в локальной сети) соединение не устанавливает вовсе.

### Значение holdout на страницу не попадает

Резерв WF-3 ценен тем, сколько раз в него смотрели. На «Обзоре» в колонке
Holdout стоит «отчёт есть, значение скрыто»; само число read-model не читает
(`WalkForwardState.has_holdout` — только факт наличия файла). Раскрытие с
журналом доступа — [ADM-5](ADM-5.md). Тест проверяет, что числа нет в HTML.

### Замер на сегодняшнем store

24 ряда, 6 пар, два таймфрейма, `ma_cross_multi_1h_4h`:

| Страница | Время ответа | Размер |
|---|---|---|
| `/` (Обзор) | 0,20–0,33 с | 13,4 КиБ |
| `/data` (Данные) | 0,20–0,21 с | 16,3 КиБ |
| `/api/status` | 0,20–0,21 с | 7,8 КиБ |

Время целиком уходит на чтение состояния (0,19 с в [ADM-1](ADM-1.md)), то есть
рендер HTML стоит порядка 10 мс. Поводов вмешаться страница показывает те же 7,
что и `status`.

### Тесты и мутации

15 тестов (`tests/test_admin_web.py`), всего в проекте 658. Модуль пропускается
без экстры `admin` — тем же приёмом, что golden-тест [BT-8](BT-8.md); в CI экстра
ставится вместе с dev, то есть страницы там проверяются, а не пропускаются.

Тесты проверены 14 мутациями — все убиты:

| Мутация | Чем убита |
|---|---|
| Вердикт не ищется по ряду (всегда «отчёта нет») | Дефект пропуска не доехал до строки |
| Неизвестное время проверки показано как время | «Время неизвестно» исчезло со страницы |
| Состояние кэшируется при сборке приложения | Страница показала старое покрытие |
| Блок расписания считается на странице сам | Строка разошлась с выводом `status` |
| `/api/status` отдаёт свой payload | Расхождение с `status_payload` |
| Дефекты названы своими словами | Формулировка разошлась с `validate-data` |
| Значение holdout подставлено в колонку | Число нашлось в HTML |
| Пустой ряд показан нулём, а не «данных нет» | Пустой store перестал объяснять себя |
| В шаблон вернулся внешний адрес | Тест на `src`/`href` с `http` |
| `HOST = "0.0.0.0"` | `uvicorn.run` получил не петлю |
| Занятый порт не проверяется | Падение вместо `AdminStartupError` |
| Отсутствие экстры падает трейсбеком | Нет понятного сообщения о `pip install` |
| CLI не ловит `AdminStartupError` | Код возврата и текст вместо трейса |
| `import fastapi` на уровне модуля в `cli/main.py` | Базовый CLI сломался без веб-зависимостей |

### Что затронуто вне нового пакета

- `pyproject.toml` — экстра `admin` (fastapi, uvicorn, jinja2) и `httpx2` в
  `dev` (его требует `starlette.testclient`); базовая установка остаётся без веба.
- `.github/workflows/quality.yml` — `pip install -e ".[dev,admin]"`, иначе CI
  молча пропускал бы все 15 тестов.
- `cli/status.py` — `_moment`/`_span`/`_periods` стали публичными
  (`fmt_moment`/`fmt_span`/`fmt_periods`): это фильтры шаблонов, и форматирование
  времени на странице обязано совпадать с терминалом.
- `cli/validate_data.py` — `_defect_parts` стала публичной `defect_parts` и
  используется в `ValidationState.defects`: третья формулировка одного и того же
  дефекта никому не нужна.
