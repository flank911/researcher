# DATA-7 — Граница `expected_end` в валидаторе против эксклюзивного `--end`

- **Эпик:** E1 — Data Core
- **Статус:** todo
- **Зависимости:** DATA-3
- **Критический путь:** нет

## Описание

`validate_candles(expected_end=...)` трактует правую границу окна как
**включительную**, а `fetch-data --end` — как **эксклюзивную**. На корректно
загруженном датасете валидатор поэтому всегда находит ровно один несуществующий
пропуск на правом краю.

## Контекст

Вскрыто на прогоне [RUN-7](RUN-7.md). Загружено `--start 2022-01-01 --end 2026-10-01`,
получено 41 616 часовых бар — это ровно число часов в `[2022-01-01, 2026-10-01)`,
то есть история полная. Валидатор с теми же границами:

```
BTCUSDT 1h: bars=41616 clean=False gaps=1 missing=1 dups=0 monotonic=True
    gap 2026-09-30 23:00 -> 2026-10-01 00:00 (1 bars)
```

«Пропущенный» бар `2026-10-01 00:00` — это бар, которого по условию загрузки быть
не должно. Так у всех шести пар символ × таймфрейм, то есть `is_clean` на чистых
данных недостижим, а реальные пропуски придётся отличать от этого шума глазами.

Docstring `validate_candles` говорит «ожидаемые границы окна (включительно по
началу)» — про правую границу умалчивает, и обе трактовки выглядят законными.
Расхождение не ловится тестами: фикстуры DATA-3 задают `expected_end` равным
времени последнего бара, при котором обе семантики совпадают.

## Решение

- Привести семантику к полуинтервалу `[start, end)` — как в `fetch-data`,
  `DuckDBStore.read_window` и конфиге эксперимента. Это одна строка в `_detect_gaps`
  плюс явная формулировка в docstring.
- Либо оставить включительную границу и исправить вызывающие стороны — но тогда
  расходятся валидатор и загрузчик, что хуже.
- Тест, который падает при любой из двух трактовок, если они разъедутся снова:
  датасет, загруженный `fetch-data`, валидируется теми же границами и даёт
  `is_clean=True`.

## Критерии приёмки (DoD)

- [ ] Полный датасет, загруженный с теми же `start`/`end`, даёт `is_clean=True`.
- [ ] Реальный пропуск на правом краю (последний бар отсутствует) по-прежнему
      находится — исправление не должно глушить проверку края.
- [ ] Семантика границ названа в docstring явно.
- [ ] Тест фиксирует согласованность с `fetch-data`, а не только внутреннюю логику.
