# ADM-2 — `status`: одна команда отвечает, живо ли всё

- **Эпик:** E10 — Админка
- **Статус:** todo
- **Зависимости:** ADM-1
- **Критический путь:** нет (но даёт почти всю наглядность за наименьшую цену)

## Описание

Команда `trading-research status`: состояние данных, расписания, валидации и
экспериментов одним вызовом, без обращения к API и без записи.

## Контекст

README описывает проверку «живо ли расписание» как процедуру из трёх шагов, и
главный из них — **запустить сбор руками** и посмотреть, догружает он что-нибудь
или говорит «актуален, догружать нечего». Проверка состояния через изменение
состояния работает, но у неё два изъяна: она ходит в сеть и она отвечает только
про один из четырёх контуров. Про остальные три (качество данных, состав
результатов, незакрытые прогоны) такой процедуры нет вовсе.

Отставание свечей на трое суток ([ADM-1](ADM-1.md), находка 1) — пример того,
что эта команда показывала бы первой строкой.

Эта команда ценна и сама по себе, и как проверка [ADM-1](ADM-1.md): если
read-model собран правильно, `status` — это только форматирование.

## Решение

```
trading-research status [--config <path>] [--json] [--strict]
```

Четыре блока, по строке на сущность — формат как у `update-data` и
`validate-data` (что было, что есть, чего не хватает):

```
Данные
  BTCUSDT 1h candles: 2022-01-01 … 2026-10-31 07:00, 41 617 бар, отстаёт на 68 часов
  BTCUSDT 1h open_interest: … 2026-11-02 18:00, 703 точки, запас до потери 27 суток
Расписание
  сбор рыночных рядов: жив (по данным), последняя итерация 2026-11-02 18:40, exit=0
Валидация
  ma_cross_multi: проверено 2026-10-31 02:01 (3 суток назад), дефектов нет
Эксперименты
  ma_cross_multi: 684 прогона, все completed, ненадёжных по числу сделок 312 (46%)
```

Код возврата: `0` — вмешательство не требуется; `1` под `--strict` — требуется.
Поводы для `1`: отставание ряда больше чем на N периодов, запас OI/LS меньше 7
суток, дефекты в последней валидации, прогоны в статусе не `completed`,
отсутствие отчёта валидации вовсе.

Порог запаса — 7 суток, и это не круглое число ради круглости: окно биржи 30
дней, интервал сбора 6 часов, то есть неделя — это 28 пропущенных итераций
подряд. Раньше — ложная тревога, позже — поздно.

`--json` обязателен: он делает командой, а не экраном, то, что потом читает
веб-админка ([ADM-3](ADM-3.md)) и внешнее расписание. Иначе единственным
потребителем состояния окажется HTML.

## Критерии приёмки (DoD)

- [ ] Команда не делает ни одного сетевого запроса и ничего не пишет в store.
- [ ] На сегодняшнем store показывает отставание свечей (трое суток) и запас по
      OI/LS — замер приложен к тикету.
- [ ] `--strict` даёт код 1 на каждом из поводов; на каждый повод есть тест.
- [ ] Пустой store и отсутствие эксперимента не падают, а печатают «нет данных».
- [ ] `--json` отдаёт те же числа, что текстовый вывод (тест на согласованность).
- [ ] Раздел README «Как проверить, что расписание живо» переписан на эту
      команду: запуск сбора руками остаётся как способ **починить**, а не
      проверить.
