# RUN-9 — `walk-forward` не показывает holdout

- **Эпик:** E7 — First real research run
- **Статус:** done
- **Зависимости:** RUN-4, RUN-7
- **Критический путь:** нет

## Описание

Команда `walk-forward` считает holdout, сохраняет `holdout_report.json` и не
печатает про него ни строки. Главный результат исследования — деградация
research-OOS → holdout — виден только тому, кто знает про файлы в
`data/results/<experiment>/wf/<symbol>/<timeframe>/`.

## Контекст

Вскрыто на прогоне [RUN-7](RUN-7.md). Полный вывод команды на конфиге с заданной
секцией `holdout`:

```
BTCUSDT 1h: 45 folds
  OOS: return=-4.55% dd=35.06% trades=306 reliable=True
...
```

Слова `holdout` в выводе нет вообще, при том что шесть отчётов записаны. Для
исследования это важнее OOS: по BTC 1h research-OOS sharpe 0.07, а holdout −1.70
(деградация 1.77) — то есть честный OOS всё равно оказался оптимистичным, и именно
это должно быть на экране.

Отдельно теряется `reliable`: два лучших holdout-результата прогона получены на
6 сделках (`reliable=false`), и без этого флага в выводе их легко принять за
успех — `sharpe` 2.47 на шести сделках выглядит убедительнее, чем есть.

Политика WF-3 реализована корректно (`cli/walk_forward.py`: резерв отрезается
первым, holdout считается один раз в конце) — не хватает только вывода.

## Решение

- Печатать строку holdout сразу за строкой OOS по каждой паре: выбранные параметры,
  значение метрики на research-OOS и на holdout, деградацию, число сделок и
  `reliable`.
- Явно говорить, когда holdout **не** считался и почему: нет секции в конфиге,
  резерв пуст, символ целиком в резерве — сейчас все три случая выглядят одинаково
  (тишина).
- Помечать нерепрезентативный holdout (`reliable=false`) прямо в строке, а не
  оставлять это на чтение JSON.
- Решить, печатать ли сводку по всем парам в конце — на шести парах отдельные
  строки читаемы, на двадцати уже нет.

## Критерии приёмки (DoD)

- [x] Holdout виден в выводе `walk-forward`: параметры, research vs holdout,
      деградация, сделки, `reliable`.
- [x] Отсутствие holdout объяснено в выводе, а не выражено тишиной.
- [x] `reliable=false` помечен в строке.
- [x] Тест на вывод команды (CliRunner), а не только на содержимое JSON.

## Как сделано

`walk_forward_from_config` возвращал `WalkForwardResult` — holdout в нём не было
вообще, поэтому команде нечего было печатать даже при желании. Теперь результат —
`PairOutcome`: прогон, отчёт holdout и `HoldoutStatus`, то есть причина, когда
отчёта нет. Строка holdout идёт сразу за OOS: OOS отвечает «сколько заработала бы
выбранная параметризация», holdout — «был ли оптимистичен сам этот ответ», и
второй вопрос для исследования важнее.

Тишина разложена на пять разных причин, которые раньше выглядели одинаково:
`NO_CONFIG` (секции нет), `EMPTY_RESERVE` (резерв по паре пуст), `NO_SELECTION`
(walk-forward не выбрал параметров), `SYMBOL_RESERVED` и `RESEARCH_EMPTY`. Два
последних случая вдобавок **убирали пару из результата целиком** — отличить «её
не считали» от «её не было в конфиге» было нельзя. Теперь такая пара остаётся в
выводе строкой «пропущен — ...».

Знак деградации назван словом, а не минусом: `деградация 1.7741` против
`прирост 1.1448 (на резерве лучше)`. Первый вариант формулировки давал
«деградация 1.1448 (на резерве лучше)» — противоречие в одной строке.

Про сводку в конце (открытый вопрос тикета) — решено печатать: на шести парах
отдельные строки ещё читаются, но ответ «честный OOS всё равно был оптимистичен»
собирается только по всем парам сразу. Сводка называет, по скольким парам holdout
посчитан, на скольких он хуже research и сколько результатов ненадёжны.

Попутно согласование числительных вынесено в `cli/text.py`: оно уже было заведено
в `update_market_data` и повторено в `validate_data`, третья копия разъехалась бы
молча.

Вывод на реальном прогоне — ровно те числа, из-за которых заведён тикет:

```
BTCUSDT 1h: 45 folds
  OOS: return=-4.55% dd=35.06% trades=306 reliable=True
  holdout: sharpe research=0.0698 → holdout=-1.7043, деградация 1.7741, сделок 54, параметры {'fast_ma': 50, 'slow_ma': 100}
...
SOLUSDT 4h: 45 folds
  OOS: return=-21.00% dd=25.99% trades=10 reliable=True
  holdout: sharpe research=-0.6394 → holdout=2.4732, прирост 3.1126 (на резерве лучше), сделок 6, параметры {'fast_ma': 10, 'slow_ma': 200}  ← НЕНАДЁЖНО: сделок меньше порога 10

итого: прогнано 6 пар, holdout посчитан по 6, хуже research на 2 из 6, ненадёжных по числу сделок 2
```

Оба «лучших» holdout-результата прогона — на шести сделках, и теперь это видно в
той же строке, а не только тому, кто откроет JSON.
