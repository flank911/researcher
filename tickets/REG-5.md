# REG-5 — Пагинация `/futures/data/*` молча теряет начало диапазона

- **Эпик:** E6 — Market Regimes
- **Статус:** todo
- **Зависимости:** REG-1
- **Критический путь:** да (тихая потеря данных)

## Описание

`BinanceMarketDataClient._paginate` предполагает, что эндпоинт отдаёт данные **от**
`startTime` вперёд. Эндпоинты `/futures/data/*` (OI, LS) отдают **хвост** запрошенного
окна — последние `limit` точек. Курсор после первого батча оказывается за `endTime`,
цикл выходит, и начало диапазона просто не загружается. Без ошибки.

## Контекст

Вскрыто на прогоне [RUN-7](RUN-7.md). Запрошено окно 28 дней (672 часовых точки),
`limit=500`:

```
$ trading-research fetch-market-data --symbol BTCUSDT --timeframe 1h \
    --start 2026-10-02 --end 2026-10-30 --series open_interest
wrote 500 rows of open_interest for BTCUSDT 1h -> data/raw
```

Записано 500 строк из 672, и это `2026-10-09 05:00 … 2026-10-30 00:00` — хвост.
Первые семь дней окна отсутствуют, команда отчиталась об успехе.

Прямая проверка эндпоинта подтверждает: с `startTime` 28 дней назад, `endTime` сейчас
и `limit=500` ответ начинается не с `startTime`, а с `endTime − 500 периодов`.

Механика в `_paginate`: `cursor = int(batch[-1][time_key]) + 1`, а `batch[-1]` — это
самая свежая точка окна, не 500-я от начала. Условие `if len(batch) < limit: break`
тоже не спасает — батч полный. Для `/fapi/v1/fundingRate` логика верна (он отдаёт от
`startTime`), поэтому дефект проявляется только на OI/LS.

## Решение

- Пагинировать `/futures/data/*` **назад**: курсор — `endTime`, на каждом шаге
  сдвигать его к `startTime` на `limit` периодов (или на минимальный таймстамп
  батча − 1), пока не дошли до `startTime`.
- Либо нарезать запрошенный диапазон на окна по `limit` периодов и запрашивать
  каждое отдельно — проще и не зависит от направления ответа.
- Инвариант, который должен ловиться: число полученных точек соответствует
  запрошенному окну, а минимальный таймстамп — не позже `startTime` + период.

## Критерии приёмки (DoD)

- [ ] Окно шире `limit` загружается целиком; покрытие проверяется по краям, а не
      только по числу строк.
- [ ] Тест на подставном транспорте, который отдаёт **хвост** окна, — фиксирует
      именно это поведение Binance, а не удобное для кода.
- [ ] `fetch-market-data` не отчитывается об успехе, если покрытие неполное.
- [ ] Регрессия на funding: пагинация вперёд по `/fapi/v1/fundingRate` не сломана.
