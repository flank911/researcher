# REG-4 — Окно retention Binance для OI/LS: кламп, внятная ошибка, пометка покрытия

- **Эпик:** E6 — Market Regimes
- **Статус:** todo
- **Зависимости:** REG-1, RUN-2
- **Критический путь:** нет

## Описание

Binance отдаёт open interest и long/short ratio **только за последние ~30 дней**.
Пайплайн об этом не знает, поэтому на любом историческом прогоне две из девяти фич
режима молча пусты, а команда загрузки падает сырой ошибкой API.

## Контекст

Вскрыто первым реальным прогоном ([RUN-7](RUN-7.md)), исследуемый диапазон
2022-01-01 … 2026-10-01.

**1. Команда падает целиком.**

```
$ trading-research fetch-market-data --symbol BTCUSDT --timeframe 1h \
    --start 2022-01-01 --end 2026-10-01
BinanceAPIError: Binance API error 400: {"msg":"parameter 'startTime' is invalid.","code":-1130}
```

`startTime` вне окна retention — это `-1130`, а не пустой ответ. Проверено: 25 дней
назад эндпоинт отвечает, 30 — уже нет. Порядок рядов в `expand_series` таков, что
funding (у которого история есть вся) успевает записаться, а OI и LS — нет, и
пользователь получает traceback вместо «эти два ряда доступны только за 30 дней».
`_validate_period` в `cli/fetch_market_data.py` уже проверяет *интервал* агрегации —
проверки *диапазона* рядом с ней нет.

**2. Пустые фичи неотличимы от отсутствия связи.**

`time_slice_features` на прогоне RUN-7: `oi_change_pct` и `ls_ratio_avg` — 114 NULL
из 114 строк. `build-features` отработал с кодом 0 и не сказал ни слова. Дальше
`analyze-regimes` печатает по этим фичам `NaN` в одном ряду с настоящими
корреляциями, то есть «данных нет» выглядит как «корреляции нет» — ровно тот класс
тихого расхождения, от которого страховал [RUN-5](RUN-5.md).

## Решение

- `fetch-market-data`: знать про окно retention для OI/LS. Диапазон за его пределами
  — либо кламп к доступному окну с предупреждением, либо явная ошибка, называющая
  окно и способ обойти (`--series funding` для истории). Выбрать кламп: при
  `--series all` на историческом диапазоне команда должна загрузить funding за всю
  историю и OI/LS за доступные 30 дней, а не падать.
- `build-features`: печатать покрытие по каждой фиче (сколько слайсов заполнено) —
  пустая фича не должна проходить незаметно.
- `analyze-regimes`: отличать «нет данных» от «нет корреляции» — отдельная пометка
  или строка покрытия под матрицей.
- Если OI/LS нужны на истории — это отдельный тикет про другой источник или про
  инкрементальный сбор по расписанию; здесь только честность про то, что есть.

## Критерии приёмки (DoD)

- [ ] `fetch-market-data --series all` на историческом диапазоне не падает: funding
      за весь диапазон, OI/LS за доступное окно, в выводе сказано, что окно урезано.
- [ ] Ошибка `-1130` не доходит до пользователя сырой: сообщение называет окно
      retention и что делать.
- [ ] `build-features` сообщает покрытие фич; фича без данных видна в выводе.
- [ ] `analyze-regimes` не выдаёт `NaN` от пустых данных без пометки.
- [ ] Тест на кламп диапазона — на подставном транспорте, без сети.
