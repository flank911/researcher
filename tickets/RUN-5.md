# RUN-5 — Заполнение режимных слотов AN-1 + CLI `analyze-regimes`

- **Эпик:** E7 — First real research run
- **Статус:** done
- **Зависимости:** REG-3, RUN-3

## Описание

Довести REG-3 до исполнимости из CLI и закрыть расхождение набора фич между AN-1 и
REG-2.

## Контекст

Два разрыва.

**1. Слоты AN-1 никогда не заполняются.**
[REGIME_SLOTS](../src/trading_research/analytics/queries.py) зарезервированы в схеме
`parameter_performance_by_slice` как плейсхолдеры, но `run_experiment_from_config`
их не наполняет — в `performance.parquet` они остаются `null`. Заполнять их должен
join с `time_slice_features` (RUN-3) через `attach_regime_features`, но вызвать его
из CLI сейчас нечем.

**2. Три фичи REG-2 выпадают из корреляций.**
`SliceFeatures` (REG-2) считает **9** числовых фич, а `REGIME_SLOTS` (AN-1)
перечисляет только **6**. Вне списка остались `adx`, `volume_zscore` и
`drawdown_from_ath`. Через join они в таблицу попадают (`attach_regime_features`
берёт все неключевые колонки), но `NUMERIC_REGIME_FEATURES` в REG-3 выводится из
`REGIME_SLOTS`, поэтому **по умолчанию корреляции считаются без них** — молча, без
ошибки. Передать их можно только явным `features=`.

Это ровно тот класс тихого расхождения, от которого страхует критический путь:
аналитик получит матрицу корреляций, не заметив, что треть фич режима в неё не
вошла.

## Решение

- Привести `REGIME_SLOTS` в соответствие с `SliceFeatures`: либо расширить до всех
  9 числовых фич, либо оставить 6 и **явно** задокументировать, что остальные —
  join-only, с тестом, фиксирующим это решение. Предпочтительно первое:
  расхождение двух списков истины — источник будущих ошибок.
- Команда:

  ```
  trading-research analyze-regimes --experiment <name> \
    [--metric total_return_pct] [--regime bull_trend] [--top 20]
  ```

  печатает матрицу `regime_correlations`, а с `--regime` — `best_params_in_regime`.
- Экспорт матрицы в CSV/Parquet по аналогии с `export-results`.

## Критерии приёмки (DoD)

- [x] `REGIME_SLOTS` и числовые поля `SliceFeatures` согласованы; несогласованность
      ловится тестом, а не ревью.
- [x] `analyze-regimes` строит матрицу корреляций по сохранённым таблицам AN-1 + RUN-3.
- [x] `--regime X` выводит top-N параметров внутри режима.
- [x] Пустой join (несовпадение `time_slice_id`) даёт явную ошибку, а не таблицу
      из `null`.
- [x] Матрица экспортируется в CSV/Parquet.

## Как сделано

`cli/analyze_regimes.py` + команда `analyze-regimes`.

**`REGIME_SLOTS` расширены до всех 10 полей** (9 числовых + `regime_label`) —
выбран первый вариант из «Решения». Списки намеренно **не** выведены один из
другого: аналитика сознательно не зависит от слоя фич (см. docstring
`analytics/correlations.py`, развязка слоёв — решение REG-3). Цена этого решения —
тест `test_regime_slots_match_slice_features`, который падает при любом расхождении
и печатает, чего именно не хватает. То есть инвариант держит тест, а не ревьюер.

**Слоты в `performance.parquet` остаются null, и это не баг.** Прогон о фичах
ничего не знает; заполняет слоты join на этапе анализа (`attach_regime_features`).
Так у `run-experiment` и `build-features` нет порядковой зависимости — их можно
считать в любом порядке и даже параллельно. Зафиксировано тестом: в таблице AN-1
слоты пусты, в склеенной — заполнены.

**Пустой join — ошибка, а не таблица из null.** Главный тихий отказ в этом месте:
left-join при разошедшихся `time_slice_id` вернёт режимные колонки пустыми, а
`pl.corr` по пустому столбцу отдаст `null` — аналитик получил бы матрицу
«корреляций нет» вместо сообщения «данные не склеились». Сообщение называет
вероятную причину (фичи собраны по другому конфигу) и способ исправить.

**Побочная правка вывода.** Матрица — 10 колонок, и дефолтный вывод polars обрезал
её до четырёх, то есть прятал ровно те фичи, ради которых тикет и делался. Команда
печатает таблицу в `pl.Config(tbl_cols=-1)`.

### Что сломалось от расширения схемы

Упал тест REG-3 `test_regime_correlations_matrix_per_param`: его фикстура строила
таблицу фич только из 6 старых колонок, что после RUN-5 стало нереалистичным —
реальная `time_slice_features` от REG-2 всегда содержит 9. Фикстура дополнена до
полного набора; проверка **не** ослаблялась.

Старые `performance.parquet`, записанные до RUN-5, деградируют корректно:
`attach_regime_features` отбрасывает только присутствующие слоты, а
`regime_correlations` фильтрует фичи по наличию — отсутствие трёх колонок не ломает
чтение, просто они не участвуют.

### Проверено на фактическом прогоне

`run-experiment` → `build-features` → `analyze-regimes` на синтетике с трендом:
матрица 3×10, все три ранее выпадавшие фичи присутствуют с осмысленными значениями
(`adx` ≈ 0.62, `volume_zscore` ≈ 0.999, `drawdown_from_ath` ≈ 0.997).
`funding_avg` / `oi_change_pct` / `ls_ratio_avg` — `NaN`, так как ряды RUN-2 в демо
не загружались; это корректное поведение, а не сбой join.
